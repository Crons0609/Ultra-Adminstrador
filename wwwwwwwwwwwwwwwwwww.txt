============================================================
ULTRA ADMINISTRADOR — MIGRACIÓN INTELIGENTE DE DATOS DESDE PDF
============================================================

Necesito implementar de manera profesional y completa el módulo:

"Migración de Datos"

dentro del Dashboard del DUEÑO DE LOCAL de mi SaaS:

ULTRA ADMINISTRADOR.

IMPORTANTE:

NO quiero simplemente permitir que el usuario almacene un PDF.

Quiero que el sistema pueda LEER, INTERPRETAR, VALIDAR y MIGRAR la información contenida dentro del PDF hacia los módulos y colecciones correspondientes de Ultra Administrador.

El objetivo es que un dueño de negocio que anteriormente llevaba su información en documentos PDF pueda subir esos documentos y evitar tener que introducir manualmente todos los datos nuevamente.

============================================================
1. OBJETIVO
============================================================

El dueño de un negocio debe poder:

1. Abrir:

Dashboard del Dueño
→ Migración de Datos

2. Seleccionar un PDF.

3. Subirlo.

4. El sistema debe analizar el contenido.

5. Identificar automáticamente el tipo de información.

6. Extraer los datos.

7. Mostrar una vista previa.

8. Permitir corregir asignaciones si es necesario.

9. Validar los datos.

10. Mostrar qué información será importada.

11. Solicitar confirmación.

12. Migrar la información a Firestore.

13. Guardar cada registro en el módulo correspondiente.

14. Mostrar un informe final.

============================================================
3. NO CREAR UN SISTEMA AISLADO
============================================================

MUY IMPORTANTE.

No crear una base de datos paralela para la migración.

Los datos migrados deben terminar utilizando exactamente la misma arquitectura de datos que utiliza actualmente Ultra Administrador.

Por ejemplo:

PDF
↓
Procesador de migración
↓
Validación
↓
Mapeo
↓
Repositorio existente
↓
Firestore
↓
Módulo correspondiente

Si ya existe:

inventoryService
productService
customerService
employeeService
etc.

REUTILIZARLOS cuando sea apropiado.

No duplicar servicios existentes.

============================================================
4. RESPETAR LA JERARQUÍA MULTIEMPRESA
============================================================

ESTO ES CRÍTICO.

Ultra Administrador es MULTIEMPRESA.

Nunca se debe importar información al lugar incorrecto.

Toda migración debe estar vinculada correctamente a:

- usuario autenticado
- propietario
- empresa
- sucursal/localización
- negocio actual

La estructura debe respetar exactamente la jerarquía existente en Firestore.

Ejemplo conceptual:

Empresa
    ↓
Sucursal
    ↓
Inventario
    ↓
Producto

Si actualmente el proyecto utiliza otra estructura, utilizar la estructura REAL existente.

NO inventar una nueva jerarquía.

- contenido

============================================================
10. CATEGORÍAS
============================================================

En el ejemplo:

Categoría:

Abanicos

Si "Abanicos" ya existe:

→ utilizar la categoría existente.

Si NO existe:

mostrar durante la vista previa:

"Categoría 'Abanicos' no existe."

Opciones:

[Crear categoría]
[Asignar categoría existente]
[Omitir]

NO crear categorías duplicadas.

============================================================
11. PRODUCTOS DUPLICADOS
============================================================

Antes de insertar un producto:

buscar si ya existe.

Por ejemplo:

"Ab sankey clásico"

Si ya existe:

mostrar:

Producto posiblemente duplicado.

Opciones:

- Actualizar existente
- Crear como nuevo
- Omitir
- Revisar

NO duplicar automáticamente.

============================================================
12. SKU
============================================================

Si el PDF no tiene SKU:

NO inventar un SKU que pueda colisionar con otro producto.

Determinar si el sistema actual tiene generación automática de SKU.

Si existe:

utilizar el generador existente.

Si no existe:

permitir dejarlo vacío cuando la estructura actual lo permita.

============================================================
13. COSTOS Y PRECIOS
============================================================

Interpretar correctamente:

C$1,792
C$2,500
C$28,672
C$40,000

No almacenar los símbolos monetarios dentro del valor numérico.

Ejemplo:

"C$1,792"

debe convertirse a un número equivalente:

1792

"C$2,500"

→ 2500

"C$28,672"

→ 28672

"C$40,000"

→ 40000

IMPORTANTE:

No asumir que todos los negocios utilizan Córdobas.

El sistema debe respetar la moneda configurada para la empresa.

============================================================
14. CANTIDADES
============================================================

Interpretar correctamente:

16

como:

quantity = 16

No convertirlo en texto.

Si aparece:

16 unidades

debe ser capaz de limpiar la unidad cuando sea posible.

============================================================
15. FECHAS
============================================================

Ejemplo:

30/03/2025

debe interpretarse correctamente como:

30 de marzo de 2025.

No confundir:

DD/MM/YYYY

con:

MM/DD/YYYY

Utilizar la configuración regional de la empresa cuando corresponda.

============================================================
34. IMPORTANTE SOBRE PDF
============================================================

El PDF puede ser:

- texto seleccionable
- tabla
- PDF generado por software
- PDF escaneado como imagen

Primero detectar qué tipo de PDF es.

Para PDF con texto/tablas:

extraer texto y estructura.

Para PDF escaneado:

dejar preparada la arquitectura para OCR.

NO implementar OCR externo de pago si no es necesario.

Si el proyecto puede funcionar sin OCR para PDFs digitales, priorizar esa opción.
